# Історія: вибір — хмарна версія

Ця версія підключена до вашого проєкту Supabase. Вона використовує Supabase Auth для входу адміністратора, таблицю `catalog_items` для спільного каталогу, Storage bucket `history-photos` для зображень і `game_results` для результатів авторизованих гравців.

## Що вже налаштовано у файлі
- Публічне читання спільного каталогу.
- Вхід і реєстрація через email/пароль у вікні адмін-панелі.
- Адмін-редагування показується лише обліковому запису з `profiles.is_admin = true`.
- Фото оптимізуються в браузері, завантажуються до Supabase Storage, а URL зберігається в каталозі.
- Кнопка «Перенести локальний каталог у хмару» переносить локальні записи та фото в спільну базу.
- Результати завершених ігор зберігаються в `game_results`, якщо гравець увійшов у свій акаунт. Гостьова гра залишається доступною.

## Перший запуск

1. Переконайтеся, що вже виконали `supabase/schema.sql` у Supabase SQL Editor. Якщо ви вже бачили `Success. No rows returned`, це нормально — схему виконано.
2. Розмістіть цю папку на статичному хостингу з HTTPS (наприклад, Vercel). Головний файл — `index.html`.
3. Відкрийте опублікований сайт, натисніть «Адмін-панель» і зареєструйте обліковий запис зі своєю електронною адресою.
4. Якщо Supabase вимагає підтвердження email, підтвердьте його в листі й увійдіть.
5. У Supabase → SQL Editor виконайте запит, замінивши `ВАШ_EMAIL` на email саме вашого акаунта:

```sql
insert into public.profiles (id, display_name, is_admin)
select id, 'Адміністратор', true
from auth.users
where email = 'ВАШ_EMAIL'
on conflict (id) do update set is_admin = true;
```

6. Оновіть сайт і знову увійдіть. У блоці «Підключення до хмари» має бути повідомлення, що права адміністратора підтверджено.
7. Натисніть «Перенести локальний каталог у хмару», щоб завантажити наявні локальні записи та фото. Не закривайте вкладку, доки не з’явиться підтвердження.
8. Створіть або відредагуйте тестовий запис і перевірте його після перезавантаження сторінки.

## Важливо про безпеку
- У файлі використано лише Supabase publishable key, який призначений для клієнтського застосунку. `service_role` або `secret` ключі не вставляйте в HTML.
- Безпека каталогу й фото залежить від RLS-політик у `supabase/schema.sql`. Не вимикайте RLS.
- Нікому, крім власного акаунта, не надавайте `is_admin = true`.
- Не розміщуйте файл як готовий публічний сайт, доки не виконаєте кроки призначення адміністратора й перевірки перенесення.
- Для роботи CDN Supabase JS і хмарного сховища потрібен доступ до інтернету.

## Якщо щось не працює
Перевірте, що SQL-схема виконана без помилок, у Supabase Authentication увімкнений Email provider, bucket `history-photos` існує, а користувач має `profiles.is_admin = true`. Повідомлення про помилку відображається в блоці «Підключення до хмари».
